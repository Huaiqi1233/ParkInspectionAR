# 三端开发顺序与接口契约确认书

> **文档性质**：本文档是 brainstorming 阶段的设计确认书（spec），也是后续 writing-plans 实施计划的**唯一设计依据**。
> **关联契约**：`docs/api-contract.md`（v0.1，三端共享数据契约，本确认书不重复全文，仅确认要点并引用之）。
>
> **For agentic workers:** 本文档经用户确认后，由 writing-plans 拆解为逐任务实施计划，按 TDD/curl 验收节奏执行，每个任务独立提交 git。

**Goal:** 打通 Unity(AR标记上报) → Go(SQLite存储) → React(管理展示) 闭环的极简可运行原型，禁止过度设计。

**Architecture:** 三端独立工程，通过 REST + JSON 契约（`docs/api-contract.md`）解耦；Go 端单包 `main`（models/store/handlers 四文件）承载存储与 API；Unity 端 AR Foundation 5.x 完成点击区分、放置预览与上报；React 端展示与管理标注。闭环链路：Unity 上报 → Go 落库 → React 展示/改状态。

**Tech Stack:**
- Go 1.22+ / Gin / `modernc.org/sqlite`（免 CGO，Windows 无 gcc 可编译）/ `github.com/google/uuid`
- Unity 2022.3 LTS + AR Foundation 5.x + ARCore（Android 真机优先）
- React 18 + Vite + TypeScript + Axios
- git 仓库（每任务一提交）

**Spec:** `docs/api-contract.md`

## Global Constraints（全局铁律，所有任务必须遵守）

1. 关键代码必须含**中文注释**，解释"为什么这么写"，不是逐行翻译。
2. 每个 Go API 端点必须提供 **curl/Postman 自测示例**（契约文档第 4 节为准）。
3. **严禁编造不存在的 Unity API 或 Go 库函数**；遇到不确定必须主动询问用户。
4. 禁止过度设计：不引入 Clean Architecture、Redux、复杂 UI、鉴权、WebSocket、微服务。
5. Unity 必须区分 UI 点击与 AR 平面点击：`EventSystem.IsPointerOverGameObject(fingerId)`（带触点参数的重载，真机必须）。
6. Go 存储用 SQLite 单文件 `park-inspection.db`，重启不丢数据。
7. React 必须实现 **Error Boundary** 处理后端宕机场景。
8. 每个任务结束必须 `git commit`，提交信息含任务编号。

## 接口契约确认要点（引用 docs/api-contract.md v0.1）

- **实体 `Marker`**：`id`(UUID, 服务端生成) / `type`(equipment|hazard|route_point|other) / `title` / `description` / `position`{x,y,z} / `rotation`{x,y,z,w} / `geo`{lat,lng} 可空 / `status` / `reporter` / `photoUrl` 恒 null / `createdAt` / `updatedAt`(RFC3339)。—— ✅ 已确认
- **6 个端点**：`POST /api/v1/markers`、`GET /api/v1/markers`(status/type/page/pageSize)、`GET /api/v1/markers/:id`、`PATCH /api/v1/markers/:id`、`DELETE /api/v1/markers/:id`、`GET /healthz`。—— ✅ 已确认
- **SQLite DDL**：`markers` 单表平铺列（pos_x…rot_w、lat/lng 可 NULL）+ status/type 索引。—— ✅ 已确认
- **补记**：`reporter` 由 Unity 客户端输入（预填"张巡检"），Go 端仅做非空与长度校验（≤32 字符），不内置默认值。

## 三端开发顺序与验收关卡

### Phase 0：仓库与工具链（git init 后即完成）
- `git init`；建立目录骨架：`docs/`、`server/`、`unity/`、`web/`；`go version` ≥ 1.22。
- 验收：`git log` 有首个提交；`go version` 输出正常。

### Phase 1：Go 后端（server/，单包 main）
- 文件：`main.go`（Gin 初始化 + 路由 + 启动 8080）/ `models.go`（契约结构体 + 信封封装）/ `store.go`（SQLite 打开/建表/增删改查）/ `handlers.go`（校验 + 业务 + 响应）。
- 实现 6 端点，信封统一；PATCH 用 `map[string]any` + 白名单字段合并；时间 `time.Now().Format(time.RFC3339)`。
- 验收：契约文档第 4 节 **7 条 curl 全部通过**；重启进程后 `GET` 仍能读到数据（SQLite 持久化验证）。

### Phase 2：Unity AR 端（unity/，AR Foundation 5.x）
- 场景：AR Session + AR Session Origin + AR Raycast Manager + 世界锚点放置。
- 交互：`Input.touchCount` 触点按下 → `EventSystem.IsPointerOverGameObject(fingerId)` 为 true 则忽略（UI 点击）；否则 `ARRaycastManager.Raycast(touchPos, hits, TrackableType.PlaneWithinPolygon)`，命中取 `hit.pose` 放置半透明预览体（Cube + 标题牌）。
- 表单：`type`（下拉）、`title`（输入）、`reporter`（输入，预填"张巡检"）→「确认上报」→ `UnityWebRequest.POST` → 解析信封：`code==0` 预览体转实体色提示成功；失败 toast + 重试按钮（本地缓存最后一条未上报数据）。
- 验收：Android 真机/模拟器上报后，curl `GET /api/v1/markers` 可见新数据。

### Phase 3：React 管理端（web/，Vite + TS + Axios）
- 页面：标注列表（分页）+ 筛选（status/type）+ 行内状态流转按钮（pending→processing→resolved/closed）+ 删除。
- Axios 拦截器统一解信封；**Error Boundary** 包裹列表组件：后端宕机显示"服务不可用 + 重试"而非白屏。
- 验收：连接本地 Go，展示 Phase 2 上报的真实数据；改状态成功且刷新后保持。

### Phase 4：闭环验收
- 全链路：Unity 上报 → Go 落库 → React 可见并流转状态 → curl 复核 SQLite 数据一致。
- 交付演示脚本（PowerShell 一键 curl 验收 + 手工 Unity/React 走查清单）。
